# Experiment Configuration

## 1. Общие параметры

| Параметр                 | Значение |
| ------------------------ | -------- |
| Транспортный протокол    | UDP      |
| Количество экспериментов | 6        |
| PING на эксперимент      | 50       |
| Интервал между PING      | 500 мс   |
| Тайм-аут PONG            | 1000 мс  |
| Порт сервера             | 54000    |
| Версия протокола         | 1        |

Измерение времени выполняется на клиенте с использованием `std::chrono::steady_clock`.

---

## 2. Экспериментальные серии

### 2.1. Baseline

Идентификатор:

```text
baseline
```

Параметры:

```text
delay = 0 ms
jitter = 0 ms
loss = 0%
```

Цель эксперимента — получить базовые характеристики UDP-соединения без искусственного ухудшения сетевых условий.

---

### 2.2. Delay 50 ms

Идентификатор:

```text
delay_50
```

Параметры:

```text
delay = 50 ms
jitter = 0 ms
loss = 0%
```

Цель эксперимента — исследовать влияние дополнительной фиксированной задержки на RTT.

---

### 2.3. Delay 100 ms

Идентификатор:

```text
delay_100
```

Параметры:

```text
delay = 100 ms
jitter = 0 ms
loss = 0%
```

Цель эксперимента — исследовать влияние более высокой фиксированной задержки.

---

### 2.4. Jitter

Идентификатор:

```text
jitter
```

Параметры:

```text
delay = 50 ms
jitter = ±20 ms
loss = 0%
```

Фактическая задержка для каждого пакета выбирается случайно в диапазоне:

```text
50 - 20 ... 50 + 20 ms
```

то есть:

```text
30 ... 70 ms
```

Цель эксперимента — исследовать изменение RTT при нестабильной задержке передачи.

---

### 2.5. Loss 5%

Идентификатор:

```text
loss_5
```

Параметры:

```text
delay = 0 ms
jitter = 0 ms
loss = 5%
```

Для каждого PING выполняется вероятностная проверка. При попадании в заданный диапазон пакет отбрасывается без формирования PONG.

Цель эксперимента — исследовать работу механизма обнаружения потерь и тайм-аутов.

---

### 2.6. Combined

Идентификатор:

```text
combined
```

Параметры:

```text
delay = 50 ms
jitter = ±20 ms
loss = 5%
```

В эксперименте одновременно применяются задержка, переменная задержка и вероятность потери пакета.

Цель эксперимента — проверить работу системы телеметрии в условиях одновременного воздействия нескольких факторов.

---

## 3. Параметры телеметрии

### Timeout

Тайм-аут ожидания PONG:

```text
1000 ms
```

Если PONG не получен в течение заданного времени, соответствующий PING получает статус `timeout`.

### SRTT

Для сглаживания RTT используется коэффициент:

```text
SRTT = 0.875 × SRTT_previous + 0.125 × RTT
```

Первое измерение RTT используется для инициализации SRTT.

### In-flight

Максимальное количество одновременно отслеживаемых запросов:

```text
256
```

### Retransmission

Повторная передача PING в рамках практической работы №2 не выполняется.

## 4. Формат результатов

Результаты сохраняются в файл:

```text
results.csv
```

Разделитель полей:

```text
;
```

Формат строки:

```text
experiment_id;sample;sequence;sent_at_ms;rtt_ms;srtt_ms;status
```

Пример:

```text
baseline;1;100;19607964;1.906;1.906;received
```

Возможные значения поля `status`:

```text
received
timeout
late
duplicate
unknown
```

---

## 5. Объём эксперимента

Для каждой серии выполняется 50 измерений.

Общее количество отправленных PING:

```text
6 × 50 = 300
```

Таким образом, итоговый файл `results.csv` содержит 300 записей измерений и одну строку заголовка.

Общее количество строк:

```text
301
```

---

## 6. Воспроизводимость

Для автоматизации запуска используется batch-скрипт.

Эксперименты запускаются последовательно:

```text
baseline
delay_50
delay_100
jitter
loss_5
combined
```

Перед каждым экспериментом запускается сервер с соответствующим профилем сетевых условий.

После завершения клиентского измерения сервер останавливается, после чего запускается следующая серия.

Для генерации случайных потерь и jitter используется фиксированное начальное значение генератора случайных чисел:

```text
12345
```

Это позволяет получать воспроизводимое поведение генератора при повторном запуске при одинаковых условиях выполнения.
